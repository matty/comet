# Paths whose values survive sanitizing, for ACP.
# Anything not listed here is replaced. Adding a line is a
# decision to publish that field's values forever.
#
# Grown past "nothing decodes ACP yet" in the promote-the-captures slice
# (2026-08-28): `crates/harness/src/acp/{mod,session,grok}.rs` now reads a
# real subset of the handshake, the session-config/model surface, the usage
# reading on a `session/prompt` reply, the tool-call state machine, and the
# `session/update` discriminator. Every line below names its own decode site
# in the task report; the standing rule is unchanged - a path earns a line
# only because something in Comet reads it, never because the value looked
# harmless.
#
# `_meta` is deliberately NOT a declared map (`surface::MAP_PATHS`). Its
# immediate children are vendor-namespaced FIELD NAMES (`x.ai/sessionConfig`,
# `claudeCode`, `steering`, `goal`, `jetbrains`, ...), one per vendor, and
# AGENTS.md's rule publishes field names on purpose. Declaring `_meta` a map
# would anonymize `.result._meta.steering.supported`'s own key and silently
# break that entry below - worse than publishing a vendor namespace string.
#
# Grok's session-config picker surface (`_meta["x.ai/sessionConfig"].options[].
# {category,id,label}`) is reviewed and genuinely decoded (grok.rs's
# `config_options`/`ladder_from_config`/`models_from_discovery`) but is NOT
# on this list. `comet-provider-sanitize` cannot promote a capture carrying
# this key at all yet -- `x.ai/sessionConfig`'s own literal `.` trips
# `validate_key`'s ambiguous-object-key rejection unconditionally (D102,
# Blocker 2), so any spelling committed here today is unreachable: escaped,
# it matches nothing the sanitizer would ever produce; unescaped, the three
# lines below are themselves indistinguishable from the nested path
# `_meta` -> `x` -> `ai/sessionConfig` -- the exact ambiguity `validate_key`
# exists to refuse. Committing a spelling before the design that decides it
# is a decision made in the wrong order. The review stands and is recorded
# verbatim in D102 rather than here; add these three back, correctly
# spelled for whatever `validate_key` resolves to, once Blocker 2 closes.
#
# `.params.update.rawInput` and `.result._meta.usage.modelUsage` ARE declared
# maps (`surface::MAP_PATHS`), so their contents never reach this file at all:
# a tool call's own parameters are keyed by that tool's parameter names (a
# union across every tool, D73's shape for Claude), and a real `steer-grok`
# capture (2026-08-28) populated `rawInput.target_file` with this operator's
# own filesystem paths.
#
# `.params.update.title` and a tool result's `content`/`rawOutput` are
# deliberately OFF this list despite `title` being read on the announcing
# `tool_call` frame (the raw tool name, e.g. "read_file" - harmless): the
# SAME dotted path is overwritten on the following `tool_call_update` frame
# with human prose that embeds a real file path ("Read `C:\Users\...`"), and
# a leaf allowlist entry cannot tell the two frames apart. `content`/
# `rawOutput` carried this operator's real file contents in that same
# capture (Grok's `read_file` tool ran during the turn) and are wholly
# undecoded regardless (`normalize::tool_update` sets `diff`/`diff_ref`/
# `diff_stats` to `None` unconditionally). `locations[].path` is genuinely
# decoded (`ReadFile.path`) but its only observed values so far are this
# operator's own paths, so it stays off pending a clean sample. `kind` and
# `status` are on this list: decoded, small fixed vocabularies
# (`read`/`search`/`other`, `pending`/`in_progress`/`completed`/`failed`),
# never personal data. See D102 for the fuller record.
#
# `.params.update.availableCommands[].name`/`.description`/`.input.hint` ARE
# decoded (`normalize::commands`, feeds the slash-command picker) and are
# still NOT on this list. Grok's `session/update` push mixes its own built-in
# commands with every skill installed on the capturing machine - this
# repository's own personal skill/plugin inventory showed up verbatim,
# `_meta.path` included, even under an isolated `GROK_HOME` with a seeded
# credential. See D102. Every `_meta` sibling on a command entry
# (`.scope`/`.path`/`.bareName`/`.qualifiedName`/`.pluginName`) stays off this
# list on ordinary undecoded grounds regardless.
